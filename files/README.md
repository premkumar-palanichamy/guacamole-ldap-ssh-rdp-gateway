# SSH/RDP Gateway — Apache Guacamole

A self-contained, Docker-based gateway portal that lets users log in with
their own LDAP credentials and connect to SSH or RDP machines — all through
a web browser. No VPN, no SSH client, no RDP client required.

---

## What This Builds

```
Browser → Guacamole Portal (http://localhost:8080/guacamole)
                │
                ├── Login verified against OpenLDAP
                ├── User sees only their permitted machines (RBAC via PostgreSQL)
                └── Connection uses NPA account (users never see target passwords)
```

**7 Docker containers on an isolated network:**

| Container        | Image                        | Purpose                          |
|------------------|------------------------------|----------------------------------|
| `ldap-server`    | bitnami/openldap:2.6         | User directory (bob, alice)      |
| `guac-postgres`  | postgres:15                  | Connections + RBAC data          |
| `guacd`          | guacamole/guacd:1.5.5        | SSH/RDP protocol proxy           |
| `guacamole-web`  | guacamole/guacamole:1.5.5    | Web portal (Tomcat)              |
| `linux-desktop`  | custom (Ubuntu+Xfce4+XRDP)  | RDP target machine               |
| `linux-server-1` | custom (Ubuntu+OpenSSH)      | SSH target machine #1            |
| `linux-server-2` | custom (Ubuntu+OpenSSH)      | SSH target machine #2            |

---

## Users, Groups, and Access

| User  | Password  | LDAP Group      | Can Access                              |
|-------|-----------|-----------------|------------------------------------------|
| bob   | bob123    | ssh-users       | Linux Server 1 (SSH), Linux Server 2 (SSH) |
| alice | alice123  | desktop-users   | Linux Desktop (RDP)                     |

**NPA Account** (used by Guacamole to authenticate TO target machines):
- Username: `npa`  
- Password: `npa_secure_password`  
- End users never see this password

## Quick Start

### Prerequisites
- Docker Desktop (or Docker Engine + Docker Compose plugin)
- `docker compose` v2+ (`docker compose` not `docker-compose`)
- ~2GB free disk space (images + builds)

### Step 1 — One-time setup (generates the Guacamole schema SQL)

```bash
chmod +x setup.sh
./setup.sh
```

This pulls the Guacamole image and runs its `initdb.sh` script to generate
`init/01_schema.sql` — the PostgreSQL table definitions for Guacamole.
You only need to run this once (or if you delete `init/01_schema.sql`).

### Step 2 — Start everything

```bash
docker compose up -d
```

Docker will:
1. Build the 3 custom machine images (desktop, server-1, server-2)
2. Pull the 4 pre-built images (openldap, postgres, guacd, guacamole)
3. Start all containers in dependency order
4. Wait for health checks to pass (LDAP and PostgreSQL)

### Step 3 — Open the portal

Wait ~60 seconds, then visit: **http://localhost:8080/guacamole**

> The `/guacamole` path is not optional — Guacamole runs in a Tomcat context.

### Step 4 — Log in

**As Bob** (SSH user):
- Username: `bob` / Password: `bob123`
- You'll see: "Linux Server 1 (SSH)" and "Linux Server 2 (SSH)"
- Click either → terminal opens in your browser

**As Alice** (Desktop user):
- Username: `alice` / Password: `alice123`
- You'll see: "Linux Desktop (RDP)"
- Click it → full desktop appears in your browser

## How Authentication Works (Step by Step)

```
1. Bob types bob/bob123 in the Guacamole login form

2. Guacamole's LDAP extension:
   → Binds to OpenLDAP as cn=admin,dc=example,dc=com (the search account)
   → Searches ou=users,dc=example,dc=com for uid=bob
   → Attempts to bind as uid=bob,ou=users,dc=example,dc=com with password "bob123"
   → If bind succeeds: Bob is authenticated
   → Searches ou=groups,dc=example,dc=com for groups where memberUid=bob
   → Finds: cn=ssh-users

3. Guacamole's PostgreSQL extension:
   → Looks up user group named 'ssh-users' in guacamole_entity table
   → Gets all connections where ssh-users has READ permission
   → Returns: "Linux Server 1 (SSH)" and "Linux Server 2 (SSH)"

4. Bob's home screen shows exactly those 2 connections — nothing else.

5. Bob clicks "Linux Server 1 (SSH)":
   → Guacamole sends to guacd: "connect SSH to linux-server-1:22 as npa / npa_secure_password"
   → guacd opens a real SSH connection to the linux-server-1 container
   → guacd translates between SSH protocol and Guacamole protocol
   → Bob's browser shows an SSH terminal (HTML5 canvas, no SSH client needed)
```

## Troubleshooting

### Check if all containers are running
```bash
docker compose ps
```
All 7 should be `running`. Health status should show `healthy` for openldap and postgres.

### View logs
```bash
docker compose logs guacamole       # Guacamole startup and errors
docker compose logs openldap        # LDAP bootstrap and queries
docker compose logs postgres        # PostgreSQL startup and SQL errors
docker compose logs guacd           # Protocol proxy errors
docker compose logs linux-desktop   # XRDP startup
```

### Verify LDAP users exist
```bash
docker exec ldap-server ldapsearch \
  -x -H ldap://localhost:1389 \
  -D 'cn=admin,dc=example,dc=com' \
  -w adminpassword \
  -b 'ou=users,dc=example,dc=com'
```

### Verify LDAP groups exist
```bash
docker exec ldap-server ldapsearch \
  -x -H ldap://localhost:1389 \
  -D 'cn=admin,dc=example,dc=com' \
  -w adminpassword \
  -b 'ou=groups,dc=example,dc=com'
```

### Check Guacamole DB connections
```bash
docker exec guac-postgres psql \
  -U guacamole_user -d guacamole_db \
  -c "SELECT connection_name, protocol FROM guacamole_connection;"
```

### Check RBAC permissions in DB
```bash
docker exec guac-postgres psql \
  -U guacamole_user -d guacamole_db \
  -c "
    SELECT e.name AS group_name, c.connection_name, p.permission
    FROM guacamole_connection_permission p
    JOIN guacamole_entity e ON p.entity_id = e.entity_id
    JOIN guacamole_connection c ON p.connection_id = c.connection_id;
  "
```

### Test SSH directly (bypassing Guacamole)
```bash
docker exec -it linux-server-1 /bin/bash    # enter the container
# OR from host: (you'd need to expose port 22 first)
```

### Test RDP connection from inside guacd
```bash
docker exec -it guacd /bin/bash
# From inside guacd, you can verify network connectivity:
nc -zv linux-server-1 22         # should print "open"
nc -zv linux-desktop 3389        # should print "open"
```

### Reset everything (delete all data and rebuild)
```bash
docker compose down -v    # -v removes named volumes (LDAP data, PostgreSQL data)
./setup.sh                # re-run setup
docker compose up -d
```

## Common Issues

### "Cannot connect to guacamole" / port 8080 not responding
- Wait longer (Guacamole takes 30-60s to start)
- Check: `docker compose logs guacamole` for Java stack traces
- Check: `docker compose ps` — is guacamole-web in "running" state?

### Login fails with bob/bob123
- LDAP may still be bootstrapping. Wait 30s and retry.
- Verify LDAP has bob: run the ldapsearch command above
- Check: `docker compose logs openldap` for LDIF load errors

### Bob logs in but sees no connections
- LDAP group name may not match DB group name (must be exact: 'ssh-users')
- Check: run the DB permissions query above
- Check: `docker compose logs guacamole` for "Cannot find group" messages

### RDP connects but shows a black screen
- Xfce4 may be loading slowly. Wait 5-10 seconds.
- Check: `docker compose logs linux-desktop` for XRDP startup errors
- Try disconnecting and reconnecting

### SSH connection refused
- Check: `docker compose logs linux-server-1`
- The sshd daemon may have failed to start

## Technology Choices (Why X not Y)

### Why Apache Guacamole?
The assignment requires it. But to explain: Guacamole is a "clientless" remote
desktop gateway — it converts RDP/SSH/VNC into HTML5, so users need only a browser.
Alternatives like Microsoft RD Gateway require Windows Server and native clients.

### Why OpenLDAP (not Azure Entra ID / Okta / FreeIPA)?
- **Entra ID / Okta**: Cloud-only SaaS. No Docker image. Requires SAML/OIDC, not raw LDAP.
  Cannot run locally in Docker Compose for a playground setup.
- **FreeIPA**: Includes Kerberos, DNS, CA, NTP — enormous for a playground (>2GB).
  Requires privileged containers and fights Docker networking.
- **OpenLDAP (bitnami)**: Runs as a single Docker container, ~200MB, configurable
  entirely via environment variables. Perfect for local development.

### Why bitnami/openldap (not osixia/openldap)?
- `osixia/openldap`: Last meaningful update was 2021. Requires manual SSHA password
  hashing via environment hooks.
- `bitnami/openldap`: Actively maintained. Auto-creates users from `LDAP_USERS`/
  `LDAP_PASSWORDS` env vars with automatic password hashing. Supports `LDAP_CUSTOM_LDIF_DIR`
  for custom entries. Follows Docker security best practices (non-root user).

### Why PostgreSQL (not MySQL)?
Both are supported by Guacamole. PostgreSQL was chosen for:
- Better Docker health check support (`pg_isready`)
- Slightly more community documentation for Guacamole setups
- Native support for `ENUM` types (Guacamole's schema uses them)

### Why Xfce4 (not GNOME or KDE)?
- **GNOME**: Requires systemd as session bus. Systemd as PID 1 inside Docker is
  complex and fragile. Results in blank screen or crash on RDP.
- **KDE Plasma**: Same systemd issue, plus ~800MB download.
- **Xfce4**: ~200MB, starts with `xfce4-session`, zero systemd dependencies. Works
  perfectly inside Docker containers.

### Why XRDP (not VNC)?
The assignment requires RDP protocol. XRDP implements the Microsoft RDP spec on Linux.
VNC uses a different protocol (VNC/RFB) — Guacamole supports both, but RDP is faster
and the assignment specifically says RDP.

### Why posixGroup (not groupOfNames in LDAP)?
- `groupOfNames` stores member as full DN: `uid=bob,ou=users,dc=example,dc=com`
- `posixGroup` stores member as uid value: `bob`
- bitnami/openldap uses posixGroup for its own groups — mixing schemas is confusing
- Guacamole's `LDAP_MEMBER_ATTRIBUTE_TYPE=uid` works cleanly with posixGroup

### Why NPA (Non-Personal Account)?
- Separates identity (who you are: bob) from access (what logs in: npa)
- Users never need to know machine passwords
- One password to rotate (in Guacamole DB) affects all sessions
- Audit trail in Guacamole shows which human connected when
- In production, NPA credentials would use SSH keys, not passwords

## Production Considerations (Not Implemented Here)

- Use LDAPS (LDAP over TLS, port 636) instead of plain LDAP
- Use SSH key pairs for NPA instead of passwords
- Put Guacamole behind a reverse proxy (nginx) with HTTPS
- Use LDAP groups from your existing directory service (AD, Okta LDAP interface)
- Implement Guacamole session recording for audit compliance
- Set `ignore-cert: false` and use a proper TLS certificate for RDP
